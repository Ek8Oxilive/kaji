## Méthode d'un lot (≈ 1 PR)
1. `git checkout main && git pull`, branche `feat/mX-…`, ticket `gh issue create --milestone … --label agent:pc-a`.
2. Sonder le vrai Proxmox **en lecture seule** (`$CLAUDE_JOB_DIR/tmp/probe*.py`, `PYTHONPATH=. .venv/bin/python -B`) avant de coder ; schémas réels, pas de mémoire.
3. Code + **faux Proxmox strict** (méthode et noms de paramètres exacts, 400 sinon) + tests ; puis **mutations** sans bytecode (`PYTHONDONTWRITEBYTECODE=1`, `python -B`), base verte d'abord ; chaque survivant = un test.
4. Suite complète en arrière-plan (≈ 4 min) sortie dans un fichier, `tail -2` seulement ; `npm run build` ; doc `docs/api/<fonction>.md` + tableau de parité.
5. Commit (`type(Mx/zone): …` + `Closes #N`), PR avec liste honnête « non testé ». Essai réel d'écriture : seulement réversible et avec l'accord d'Enzo.
6. **Après le déploiement (consigne d'Enzo, 2026-11-09)** : ouvrir Kaji dans le navigateur (extension Claude) et vérifier que **toutes les fonctions du lot marchent dans l'interface web**, comme dans l'interface Proxmox (page, boutons, chaque fenêtre, aperçu `dry_run`, écritures réversibles autorisées) ; noter dans la PR ce qui a été vu dans le navigateur et reporter les fonctions manquantes dans `docs/parite-proxmox.md`.
7. **Captures du README, à CHAQUE PR (consigne d'Enzo, 2026-11-09 puis 2026-11-10)** : après le déploiement d'une PR, mettre à jour la section « Captures d'écran » du `README.md` (images dans `docs/captures/`) avec **chaque page, chaque onglet et chaque fenêtre d'action** nouveaux ou modifiés, **plusieurs écrans si la page est longue** (défilement de 700 px, fenêtre 1400×900), et **un petit texte d'explication sous chaque capture**. **Vérifier aussi ce que l'autre agent a ajouté depuis la dernière fois** (`git log`, PR mergées) et le capturer. Lecture seule : ouvrir les fenêtres puis les fermer sans valider. Ne pas montrer les pages Connexions et Compte (tokens, mots de passe). **Le dépôt est public** : avant de capturer, remplacer dans la page les noms de machines réels par des exemples (`media-server`, `dns-lxc`…) et `192.168.1.x` par `10.0.0.x` (script de remplacement du texte avec un `MutationObserver`, navigation par `location.hash` pour le garder actif), masquer les noms de domaine internes, et ne jamais commiter une image non masquée. **Avant de pousser : vérifier qu'aucune capture n'est en double** (même `md5`, images quasi identiques, même image ou même légende référencée deux fois dans le README, fichier non référencé) et supprimer le doublon.
8. **Éviter les doublons entre agents** : avant de coder un lot, `git fetch` + `git branch -r`, relire cette page sur `origin/main` (« a repris », « PR en cours ») et **commenter « je prends » sur le ticket tout de suite** (le 2026-11-10, deux agents ont codé le lot #151 en parallèle : une PR a dû être fermée).

## Retrouver le code sans tout lire
`grep -i mot docs/CARTE.md` (carte générée : rôle et routes de chaque fichier), puis ouvrir seulement le fichier trouvé (son `*spec.py` pour la validation, son routeur, `tests/test_<module>.py`). Fin de lot : `python3 tools/carte.py > docs/CARTE.md`.
